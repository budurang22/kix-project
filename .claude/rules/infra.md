# 인프라·배포 규칙

기준 문서: `docs/tech-stack.md`, `docs/decisions.md` DEC-017. 설정 파일 작성, 명령어 실행, 실제 배포는 개발자가 직접 한다. Claude는 개념, 공식 문서, 예시, 리뷰를 맡는다.

- 구조: EC2 단일 인스턴스, Docker Compose, 컨테이너 3개(frontend=Nginx, backend, mysql), 내부 네트워크 통신
- 외부 공개는 80/443만. 8080과 3306은 **호스트와 외부에 직접 게시하지 않는다**. SSH(22)는 개발자 IP로만 제한한다. 로컬 개발에서만 MySQL 호스트 포트를 `127.0.0.1`에 바인딩한다 (DEC-024). 서버용 Compose에는 넣지 않는다.
- 배포 자동화는 GHCR와 SSM을 우선 검토한다. 일정 부족 시 이미지 등록 자동화 + 수동 배포부터 한다. Actions에서 SSH로 접속하는 구성은 SSH 제한과 충돌하므로 안내하지 않는다 (`docs/tech-stack.md` 8.2장).
- MySQL은 named volume으로 영속화한다. 컨테이너 재생성 후 데이터 유지를 검증한다 (T-13).
- 이미지에 비밀값을 넣지 않는다. 서버 `.env`와 GitHub Secrets만 사용하고, 장기 AWS Access Key보다 OIDC를 우선 검토한다.
- 워크플로는 프론트·백엔드를 분리하고 `paths` 필터를 쓴다. 서드파티 액션은 버전(가능하면 커밋 SHA)을 고정한다.
- 배포는 단계적으로: 수동 → CI → CD → HTTPS. 못 한 단계는 "미적용"으로 기록한다.
- 분리 가능성: 백엔드 무상태, DB 접속 정보 환경변수화, 프론트 API 주소 한 곳 정의, CORS 설정화.
- 도메인이 없으면 HTTPS를 적용하지 않고 실제 개인정보를 쓰지 않는 데모로 제한한다.
- 배포 결과는 외부 브라우저에서 접속해 확인한 것만 "검증"으로 적는다.

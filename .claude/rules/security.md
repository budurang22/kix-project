# 보안 규칙

- 비밀번호, JWT Secret, AWS 자격 증명을 Git, 문서, 로그, 대화에 남기지 않는다. 비밀값을 출력하지 않는다.
- 실제 값은 `.env`에만 두고 Git에서 제외한다. 예시 파일에는 변수 이름만 둔다.
- 비밀번호는 BCrypt로 해시한다. 로그와 응답에 해시도 노출하지 않는다.
- 관리자 계정은 공개 회원가입으로 만들 수 없다. 가입 API는 항상 일반 사용자 역할만 부여한다.
- 인가: 역할 검사와 리소스 소유자 검사를 모두 한다. 타인의 주문은 존재 여부를 숨긴다 (404).
- 입력값은 서버에서 검증한다. SQL은 문자열 연결 없이 JPA 또는 파라미터 바인딩만 쓴다.
- 가격은 서버가 계산한다. 클라이언트가 보낸 가격은 신뢰하지 않는다.
- 인증 정책(확정, DEC-024): Access Token 60분, Refresh Token 없음, `Authorization: Bearer`, Stateless, 인증 실패 401·권한 부족 403. 쿠키·세션·Basic·remember-me로 인증하지 않는다(CSRF 비활성화의 전제). 쿠키 인증을 도입하려면 먼저 협의한다. 한계(XSS, 탈취, 만료, 로그아웃)는 `design-revision-v1.2.md` 7.5장.
- 401/403은 `AuthenticationEntryPoint`·`AccessDeniedHandler`에서 명시적으로 지정하고 테스트로 검증한다 (공식 문서에 기본 상태 코드 설명이 없다).
- 8080(백엔드)과 3306(MySQL)은 외부에 공개하지 않는다. HTTPS 없이 배포하면 실제 개인정보를 쓰지 않는 데모로 제한한다.
- `.env`와 비밀 파일은 읽지 않는다 (`.claude/settings.json`에서 차단).

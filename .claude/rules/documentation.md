# 문서 규칙

## 1. 문서 구조

- 기준: 로컬 `docs/`. Notion은 읽기만 한다.
- 문서 내부 목차는 `1.`, `2.`, `3.` 형식으로 통일한다.
- 작성 가능: `docs/**`, `CLAUDE.md`, `.claude/**`, `design/approved.md`

## 2. 기록 파일

| 파일 | 내용 |
| --- | --- |
| `docs/progress.md` | 현재 단계, 완료·진행 중·다음 작업. 구현 완료와 학습 완료를 구분 |
| `docs/decisions.md` | 기술 선정·설계 결정 (상태: 확정/제안/보류/대체) |
| `docs/references.md` | 기술과 버전, 공식 URL, 확인 날짜, 참고 내용, 적용 이유, 실제 검증 여부, 검증 결과 |
| `docs/session-log.md` | 세션별 기록 |
| `docs/learning/` | 학습 기록과 면접 질문 (실제 학습 진행에 맞춰 작성) |

## 3. 작성 원칙

- 공식 문서에서 확인한 **사실**과 프로젝트 **자체 결정**을 구분한다.
- 실제 실행 결과와 예상·목표 값을 구분한다. 측정하지 않은 수치는 쓰지 않는다.
- 공식 출처로 확인하지 못한 내용은 "미확인"으로 표시한다.
- 중요한 설계 변경은 승인 후 `decisions.md`에 기록하고 관련 문서(ERD, API, 테스트)를 함께 갱신한다.
- 비밀값은 어떤 문서에도 적지 않는다.
